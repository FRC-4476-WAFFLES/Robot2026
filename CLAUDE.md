# Robot2026 — Leo (FRC 4476 WAFFLES)

WPILib + AdvantageKit robot code. Java 17, Gradle (GradleRIO), CTRE Phoenix 6, PathPlanner, Limelight. `build.gradle` names the season.

## Commands

```bash
./gradlew build            # compile + tests
./gradlew simulateJava     # run the simulator (sim GUI + DriverStation enabled)
./gradlew deploy           # deploy to the roboRIO (team 4476)
./gradlew replayWatch      # AdvantageKit log replay watcher
```

On Windows use `gradlew.bat`. There is no test suite — `src/test/` does not exist.

## Layout

| Path | Contents |
|---|---|
| `frc/robot/` | `Robot`, `RobotContainer` (static wiring + bindings), `RobotState` (state + `Trigger` factories), `Controls` |
| `frc/robot/subsystems/<name>/` | The `Foo` / `FooIO` / `FooIOTalonFX` / `FooIOSim` trio |
| `frc/robot/commands/<area>/` | Static command factories (`DriveCommands`, `ShooterCommands`, …) |
| `frc/robot/autos/` | `SequentialCommandGroup` autos; `adaptable/` is the dynamic auto system |
| `frc/robot/data/` | `Constants`, `FieldConstants`, `TunerConstants`, generated `BuildConstants` |
| `frc/robot/utils/lib/` | Team library — `ExpandedSubsystem`, `EpochTimer`, `WafflesUtilities`, splines |
| `frc/robot/utils/hardware/` | `TalonFXIO`, `PhoenixHelpers`, `DeferredRefresher` |
| `frc/robot/utils/vendor/`, `utils/vision/LimelightHelpers.java` | Third-party files copied in — keep diffable against upstream |
| `*/obsolete/` | Dead code kept for reference. Do not edit. |

`BuildConstants.java` is generated by the `gversion` plugin at build time and is gitignored — never edit it.

## Safety

**Never run `./gradlew deploy` (or any `deploy*` task) unless a human explicitly asks for it in that moment.** Deploying restarts robot code on real hardware; if the robot is powered and someone is near it, that moves mechanisms. Build, test, and simulate freely — none of those touch a robot.

Simulation and tests cannot enable a real robot. They run in a desktop JVM with no connection to a roboRIO, `DriverStationSim` only drives the simulation HAL, and `Constants.getMode()` resolves to `SIM` off-robot so every subsystem gets its `*IOSim` layer.

## Hard rules

- **Every hardware read goes through an IO layer** and is read back from the `inputs` object, never from `io` or a motor handle. This is what makes log replay work, and nothing warns you when you break it.
- **`Timer.getTimestamp()`, never `Timer.getFPGATimestamp()`** in new code. The latter breaks replay. ~13 existing calls are pre-existing debt, not the standard.
- **Every motor gets a current limit**, applied via `PhoenixHelpers.tryConfig` so CAN failures surface.
- **Motors are `TalonFXIO`, not raw `TalonFX`** — that's what registers status signals for the single grouped CAN refresh.
- **Every CAN device is an entry in the `Ports` enum**, constructed as `new TalonFXIO(Ports.HOOD_MOTOR)`. CAN IDs are only unique per bus, so an ID alone doesn't identify a device. Drivetrain is the exception — it lives in the generated `TunerConstants`.
- **Never hardcode red-alliance field coordinates.** Use `BlueRelativeTarget` / `WafflesUtilities.FlipIfRedAlliance`.
- **2-space indent, spaces not tabs, 120 columns.** Enforced by `formatter.xml` on save.
- This code runs on a robot at competition. Prefer a boring change that is obviously correct over a clever one.

## Skills

Three project skills in `.claude/skills/` carry the detail:

- `frc-code-style` — formatting, naming, imports, headers, hygiene. Loads automatically on any Java file.
- `frc-subsystem-pattern` — recipes for adding a subsystem, IO layer, command, constant, or auto.
- `frc-advantagekit-logging` — logging keys and the replay determinism rules.
